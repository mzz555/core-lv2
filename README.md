# CORE · 单人深度恋爱侧写系统

> 本仓库是产品的**设计说明文档集**，不是代码仓库。
> 它的用途只有一个：让协作的 AI（GPT）在读完之后，能够理解这个产品的完整构思，并对**一个具体的、当前悬而未决的理论设计问题**给出判断。

---

## 一、如果你是被邀请来协助判断的 AI，请先读这里

### 需要你判断的问题

**产品的主理论已经锁定：图式疗法（Schema Therapy），八个与恋爱相关的早期不适应图式。这一层不再变动。**

问题是：**在这个前提下，理论层和设计层是否还需要引入其他心理学 / 认知理论？如果需要，应该在哪些位置引入、引入哪些？**

### 三条硬性约束（请在这个边界内回答）

1. **不要建议增加图式。** 八个图式是产品的骨架，已经完成采集标准、标注体系、素材采集，不再增减。
2. **不要建议更换主理论。** 不要提议用依恋理论、大五人格、或其他框架替代图式疗法。
3. **不要建议需要治疗师在场的方案。** 交付形态是微信小程序 + 一份自动生成的文字报告，全程无人工介入。

### 我们希望你输出的东西

1. 对文档 `docs/06-待决问题-理论增补.md` 中**已提出的四个候选位置和候选理论**，逐一给出判断：成立 / 不成立 / 需要修正，并说明理由。
2. 指出我们**漏掉的位置**——有没有哪个结构性空缺我们没意识到。
3. 指出我们**选错的理论**——有没有哪个位置上，存在比我们选的更贴合的理论。
4. 如果你认为"不需要引入任何额外理论"，请直接说，并论证图式疗法本身如何覆盖我们列出的四个空缺。

## 三、产品一句话

**CORE 是一个恋爱心理侧写系统。它不给用户贴标签，而是把用户反复碰壁的那个"困境模型"照给他自己看——让他看见自己相信的因果、因此做的事、和反复得到的结果，三者其实是同一个闭环。**

CORE 是代号，取自四个词的首字母：**C**onnection（连接）、**O**bservation（观察）、**R**eflection（反射）、**E**volution（演化）。
