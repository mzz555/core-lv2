# 01 · 背景与设计原点

## 1.1 产品从哪里来

产品的最初灵感来自一个观察：在大模型陪伴类产品中，大量用户把 AI 当成心理树洞，讲述自己在恋爱中的困境——不被理解、反复冲突、屡屡失败。

把这类倾诉大量地放在一起看，会发现一件事：**很多人的恋爱困境不是"运气不好"或"遇人不淑"，而是同一种模式在反复上演。** 换了对象，换了城市，换了年龄阶段，碰壁的形状却几乎一样。

更进一步：**当事人自己看不见这个模式。** 他能清楚地描述每一段关系里发生了什么，但看不见那条贯穿所有关系的线。他会把重复归因为运气、归因为对方、归因为命运——而这恰恰是模式得以延续的原因。

> **说明**：上述观察是产品的**灵感来源**。产品实际使用的语料并非来自任何私有对话数据，而是从抖音、小红书等公开平台的评论区采集的用户自述，经过脱敏和质量筛选后入库。详见 [`04-数据体系-采集与标注.md`](04-数据体系-采集与标注.md)。

## 1.2 旗舰案例：一个典型的困境模型

这个案例是整个产品论证的压缩包。理解了它，就理解了产品要做什么。

**当事人**：男性，26 岁，贵州小镇出身，双一流院校毕业，一线城市大厂程序员，年薪约 25 万。六岁时因意外右小腿截肢，现佩戴假肢。大学时期有过一段恋爱，毕业时分手，女方给出的分手理由是"在意他的腿"。

**他的后续行为**：他得出结论——自己谈不成恋爱是因为别人在意他的腿。既然身体有缺陷，就需要用别的东西补上，于是在后续交往中反复强调自己的经济能力和职业成就，同时对腿的话题绝口不提。恋爱依然不顺。他逐渐把恋爱和人生的不幸福归结于命运，反复自问"为什么被选中的是我"。

### 这个案例的真实结构（五步链条）

表面看是"因为腿所以谈不成恋爱"。实际结构是：

**第 1 步 · 归因锚定**
分手时对方给了一个理由，他把这**一个数据点**当成了因果定律。而分手时说出口的理由往往是体面替代品——"你的腿"是一个对方无法反驳、也不显得刻薄的说法，真实原因可能是异地、可能是他情感上的不在场。他没有条件去证伪，就当真了。

**第 2 步 · 补偿模型**
身体有缺 → 用经济补足。这把亲密关系换算成了一本账。

**第 3 步 · 行为固化**
强调收入和能力，回避腿的话题。**而回避才是真正的杀伤**——遮掩传递的是羞耻，羞耻在亲密关系里会传染，他实际上是在要求对方也把这件事当成不可说的。他为了防止被嫌弃所做的事，恰恰制造了那份距离。

**第 4 步 · 自我实现**
关系再次失败。模型被"验证"了。

**第 5 步 · 归因升级到命运**
这一步是保护性的。**命运不可检验。** 闭环到此完成，模型变得不可证伪——这才是真正的牢笼，因为他把所有反例的入口都关上了。

### 从这个案例得出的三个产品判断

**判断一：产品的对象不是"人格类型"，是"归因回路 + 自我实现的行为链"。**
给用户贴标签（回避型、讨好型）意义有限——很多人早就知道自己是什么型。有价值的是把「你相信的因果」「你因此做的事」「你反复得到的结果」三者并排摆出来，让他自己看见那个闭环。

**判断二：可干预的点在第 3 步和第 1 步，不在情绪层。**
第 3 步是今天还在做的行为，可指认、可改；第 1 步是那个从未被检验的归因，可以设计检验。情绪本身不是抓手。

**判断三：第 5 步是最难的一步，也是现有理论覆盖不到的一步。**
参见 [`06-待决问题-理论增补.md`](06-待决问题-理论增补.md) 第 2 节。

## 1.3 产品目标

让用户**理解自己的困境模型**，从而有机会走出反复碰壁的循环。

注意目标的措辞：是"理解"，不是"被诊断"；是"看见"，不是"被告知"。这个区别决定了后面所有的设计原则。

## 1.4 目标用户

| 维度 | 定义 |
|---|---|
| 性别 | **女性优先**（MVP 阶段。男性版本为二期，数据结构预留性别字段） |
| 年龄 | 25–32 岁为主 |
| 城市 | 一线 / 新一线 |
| 学历 | 本科以上 |
| 关系状态 | 单身、刚分手、或在关系中反复受困 |
| 恋爱经历 | 1–3 段 |

## 1.5 交付形态

- **载体**：微信小程序
- **流程**：用户答题 → 算法判定 → AI 生成报告
- **产出**：一份深度侧写报告
- **定价**：¥29.9
