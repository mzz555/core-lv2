# 05 · 产品与算法设计

> 任何理论增补方案**必须能落进这个流程**。这一章定义了增补的可行性边界。

---

## 5.1 整体链路

```
八个图式（理论根基）
        ↓
抖音 / 小红书真实评论（语料）
        ↓
标注体系（把评论映射到图式 + 面向 + 应对方式 + 触发场景）
        ↓
生成题目（所有题目基于真实素材，不凭空编写）
        ↓
【用户答题】24 道必答题
        ↓
【算法】筛出命中最高的 top3 图式
        ↓
【用户答题】自适应验证题（针对 top3）
        ↓
【算法】判定最终结果
        ↓
【撰写 agent】不计算，只按算法结论解读
        ↓
深度报告（¥29.9）
```

**算法与 agent 严格分离**，这是硬设计：算法负责一切判定，agent 只负责表达。这保证同样的输入永远得到同样的判定，报告口径不会漂移。

## 5.2 答题设计

### 必答题（24 道）
- 8 个图式 × 每图式 3 道
- 目的是**筛选**，不是精确测量
- 产出：命中最高的 top3 图式

### 自适应验证题
- 只针对 top3 图式追问
- 目的是在相关簇内做**鉴别**，并确定应对方式
- 素材来源：[`03-理论基础-八个图式.md`](03-理论基础-八个图式.md) 3.5 节的辨析规则可直接转为"同情境、不同内心独白"的迫选题

### 题量的硬约束
**24 道必答题已经是微信小程序的上限区间。** 完成率在 30 题之后会明显下滑。任何增加题目的方案，必须在这个预算内做取舍。

## 5.3 输出形态（倾向方案，未最终确定）

**主图式 + 次图式 + 应对方式**，而非单一图式。

理由：
- 图式高度相关，强行单选会在两个几乎同分的图式之间做一次不诚实的判定
- 组合本身才是故事。例如 SCH6 自我牺牲 + SCH8 苛刻标准 = "我为你付出这么多，你怎么还达不到我的标准"——这个模式单看任何一个都描述不出来

---

## 5.4 报告结构（由素材体系反推）

依据 [`04-数据体系-采集与标注.md`](04-数据体系-采集与标注.md) 4.4 的内容目标分类，报告的骨架已经隐含成型：

| 模块 | 内容 | 对应原则 |
|---|---|---|
| 1. 你的模式是什么 | 主图式 + 次图式 + 应对方式 | Reflection |
| 2. 这个模式从哪来 | 童年成因故事 | "给模式一个正当的出身" |
| 3. 它今天在替你做什么 | 应对方式的具体表现 | 把模式和人分开 |
| 4. 它如何反过来伤了你 | 反讽副作用段 | 自我实现的闭环 |
| 5. ？ | **空缺** | 对应旗舰案例第 5 步 + Evolution |

**模块 5 是空的。** 现有理论框架提供不了内容。

### agent 的写作硬约束（拟定）
- **只能引用用户的真实作答**，禁止编造情节
- **禁止宣判式表述**，必须呈现证据让用户自己得出结论
- **禁止品性归因**（"你太自卑""你把爱情当交易"）
- 优先使用用户素材库中的**原生外化语言**

> 目前这些约束只是价值主张，**缺少可执行的方法论**。见 [`06-待决问题-理论增补.md`](06-待决问题-理论增补.md) 位置三。

## 5.6 尚未决定的技术问题（不在本次判断范围，但会受理论增补影响）

1. **计分方式**：绝对分加总 vs 被试内标准化（z 分）vs 迫选。若用 5 点李克特直接加总，"什么都同意"和"什么都不太同意"的人排出的 top3 反映的是答题风格而非图式结构。
2. **停题规则**：自适应阶段最多问几题？分不开时报组合还是报"两套模式在打架"？
3. **付费点位置**：答完即付，还是先给免费预览再付？
4. **危机识别**：SCH4（出轨/PUA）和 SCH5（控制型关系）的题目会命中正在经历真实危险的用户。需要在**算法层**（不是 agent 层）做识别与分流。
