# 04 · 数据体系：采集与标注

> 这一章说明"手上已经有什么数据"。判断理论增补时，需要知道哪些维度已经采集、哪些没有——**已采集但未使用的维度，是成本最低的增量来源。**

---

## 4.1 语料来源与原则

**核心原则：所有测评题目必须基于真实的用户自述生成，不凭空编写。**

- **来源平台**：抖音评论区、小红书、豆瓣、知乎、微博，以及少量私人案例（充分脱敏）
- **采集方式**：定位心理类博主（粉丝 50 万–500 万）的评论区，用四层关键词清单检索，进入评论区二次搜索
- **甜蜜区策略**：优先采集**点赞数 50–500** 的评论——点赞过万的已被高度传播、金句化、套路化；点赞个位数的质量参差；50–500 是"真实自白被识别但没有被广泛传播"的区间

---

## 4.2 优质素材的七条判别标准

每条素材必须全部满足七条，少一条即降级。

| # | 标准 | 判别要点 |
|---|---|---|
| 1 | **有具体事件，不是抽象自述** | 能看到时间、对方做了什么、自己做了什么、心里想什么——四件具体的事 |
| 2 | **有"知道但做不到"的内在张力** | 理性认知与情绪反应的矛盾。**这种张力是图式存在的核心标志** |
| 3 | **有反讽副作用的影子** | 能看到用户的应对策略**反过来伤害了她自己**——这是产品的核心 |
| 4 | **语言真实**，不文学化、不网络化 | 是不是真实目标用户和朋友讲事情时会用的语言 |
| 5 | **背景符合目标定位** | 能推断出 25–32 岁、一线/新一线、本科以上、单身或刚分手 |
| 6 | **能指向某个具体面向** | 能标注出 1–2 个具体面向；标不出说明素材不够精准 |
| 7 | **脱敏干净** | 本人看到也认不出 |

> **标准 2 和标准 3 是整套体系里最重要的两条**。它们不是数据清洗规则，而是**图式存在的操作性定义**：
> - 标准 2 对应旗舰案例的第 1–2 步（信念与现实的冲突）
> - 标准 3 对应第 3–4 步（自我实现的闭环）

**防污染规则**：明确排除"恋爱脑""渣男""PUA""舔狗""普信男""教你几招"等关键词——这些内容的焦点是"对方多坏"（外部归因），不是"我形成了怎样的模式"。

判别口径：**这条素材的主角是"那个坏人"，还是"用户自己的心理模式"？** 前者舍弃，后者保留。

## 4.3 标注字段（每条素材必填）

| 字段 | 取值 |
|---|---|
| 素材编号 | A- 至 H- 前缀 + 序号（对应 SCH1–SCH8） |
| 来源平台 / 来源细节 | 便于回溯 |
| 可信度自评 | 1–5 分，**低于 3 分不入库** |
| **体现的核心面向** | 该图式 8 个面向中的 1–2 个 |
| 图式亚型 | SCH3（A/B/C）、SCH5（需求/情绪/混合）特有 |
| 创伤来源类型 | SCH4 特有，7 种 |
| 关系阶段 | 暧昧期 / 初期 / 稳定期 / 分手中 / 分手后 / 长期单身 |
| **触发场景类型** | 每个图式 8 种，用于题目情境覆盖 |
| **应对策略类型** | 屈从 / 逃避 / 过度补偿 / 健康反应 |
| **副作用程度** | 弱 / 中 / 强 |
| 用户年龄段、城市层级 | 推测 |
| 是否带反思 | 是 / 否 |
| **支持的核心目标** | 见 4.4 |
| 关键引用句 | 最有冲击力的一句**用户原话** |

**标注原则**：一条素材只标一个主导图式；拿不准标"不明"不硬填；核心面向最多 2 个。

## 4.4 「支持的核心目标」——这个字段实际上定义了报告结构

每条素材标注它主要服务于哪个内容环节：

| 内容目标 | 用途 | 理想占比 |
|---|---|---|
| **题目情境** | 写测评题 | 40% |
| **反讽副作用段** | 报告中"你做的事如何反过来伤了你" | 25% |
| **AI 假设揭示话术** | 引导用户自己说出结论的话术 | 15% |
| **童年成因故事** | 报告中"这个模式从哪来" | 10% |
| 通用支持 | 素材池 | 10% |

> **重要**：这四类内容目标已经隐含定义了报告的模块结构，且与 CORE 框架对应：
> - 童年成因 → 给模式一个正当的出身（对应"不指责"原则）
> - 反讽副作用 → 自我实现的行为闭环（对应旗舰案例第 3–4 步）
> - AI 假设揭示 → "让用户自己说出口"（对应 Reflection）
> - 题目情境 → 测评题（对应 Observation）

**但缺一块**：没有任何一类对应旗舰案例的**第 5 步（归因升级到命运）**，也没有任何一类对应 **Evolution**。

## 4.5 用户自发的外化语言（重要资产）

采集到的素材中，用户经常**自发地把模式当成一个外部实体来说**：

> "那个挑剔的开关一旦打开就关不掉"
> "我那套完美清单不是在帮我筛人，是在帮我把好的人一个个推开"
> "我可以爱一个人，但我永远不会把我的钱、我的退路交给任何人"
> "我哪是不想麻烦他，我是从小就没人在我难受的时候问过我"
> "每次验证完，我反而更不确定"

这些是现成的"模式外化"语言。报告如果用**用户自己的比喻**来命名她的模式，比任何术语都更不伤人、也更粘。

## 4.6 已知的数据体系问题

1. **SCH1 的采集文档明显薄于其余七个**——缺打标维度、缺搜索关键词清单、缺案例示范。而 SCH1 恰恰最需要采集支持：**羞耻的定义就是不说**，这类用户最不会在评论区自述。
2. **字段体系在八个图式之间不齐**——「支持的核心目标」字段在部分图式的文档中缺失。
3. **交叉信息被"单主导图式"原则丢掉**——SCH1×SCH8 这类交叉素材最有价值，但目前只能写在备注里，检索不到、进不了算法。
4. **标注为单人闭环**——单人采集、单人标注、单人自检，无双标一致性检验、无外部专业盲审。
5. **语料存在平台偏差**——评论区叙事以"被辜负"为主，会让 SCH2/SCH3/SCH4/SCH6 素材充足，而 SCH1（羞耻不说）、SCH8（会讲成"我要求高有错吗"而非困境）天然稀缺。

> 这些问题正在通过"审核 + 补构造"流程解决，**不属于本次需要判断的范围**。
